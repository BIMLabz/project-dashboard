You spent a week writing file docs for your coding agent. The source is already on disk.

Arman and Molybog score a description by whether another model can rebuild the file from that text alone and still pass the original tests. They treat the describe prompt as a small harness (the code around the model that shapes what it writes) and search until the rebuilt file matches the original closely enough to pass every test.

With the source file removed, optimized docs actually help. Mean share of tests passed on their sample files:

0.08 vs 0.71

Issue alone versus optimized description.

With the source present, which is how agents normally work, neither compact docs nor retrieved notes from past tasks beat the issue alone across two kinds of models and ten code projects. Longer docs were often worse. A restatement of readable code becomes a distractor.

If the agent can already read the source file, skip writing the docs. Docs pay when the source cannot be loaded.
