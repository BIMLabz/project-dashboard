You ask for a SQL fix. The agent writes one shot. You never run it. "I wrote the fix" is fanfiction.

Coding is write, execute, read the failure, fix. Execution feedback is the observation.

InterCode (Yang 2023) makes that loop a standard: code is the action, the runtime reply is the observation, until submit.

Same model, interactive vs single-turn. GPT-4 SQL in the paper: 9.1% -> 73.7% (Single Turn -> Try Again, n=10).

Late turns also plateau. Dumping every old error into context becomes tax, not skill. Keep the failing-then-passing run. Do not keep the whole diary forever.
