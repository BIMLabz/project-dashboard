Verified: Table 1 + §4.1 — Letta 61.8% ±2.3 / $42.1 ±1.6 vs JAZ invoke 69.9% ±1.8 / $18.3 ±0.3 on StuLife far-recall (207 tasks, GPT-5.4 nano high, 3-run means).

Your agent is seventy handoffs deep into a long session. The last quiz needs a detail from hundreds of steps ago. Compaction already dropped it. The memory search tool came back with the quiz text itself, not the lecture that taught the answer.

Li et al. keep the full conversation history as a variable in the REPL (the live code session the model writes into). When the context window fills, the agent starts a subagent (a nested run) and passes that history by reference, instead of pasting a summary or hoping a search API finds the right line. They call this loop invoke inside a minimal framework named JAZ. No separate memory product. No vector store in the middle.

Same GPT-5.4 nano, share of StuLife far-recall tasks finished (207 tasks in a long student-life sim that need a fact delivered more than 50 tasks earlier), Letta specialized memory harness vs JAZ history-as-variable:

61.8% vs 69.9%

Cost was about half ($18.3 vs $42.1).

If your long session keeps losing the one line that mattered, give the agent the raw history as something it can program against, not only a search box over a compacted log.
