Live OpenAI-compatible guest in a tiny harness - part 7

For six parts, the model in this series has been an actor reading from a script. It asked for hello.txt every time, in exactly the same words, because we wrote its lines. Now set one environment variable (a named setting your shell hands to every program it starts), run npm run live, and a real chat model on a server somewhere reads the task and decides for itself what to ask for.

Last time we gave the harness, the small program wrapped around the model, a basic text user interface (TUI): a plain terminal view that reprinted each event of the run as a tagged line right after it was written to the log file. The log stayed the source of truth, and the screen only followed it. Catch up here: Basic TUI in a tiny harness - part 6.

This time we swap the scripted guest for a live one, behind the same single method the loop has always called. OpenAI-compatible means any service that accepts requests in the same format as OpenAI's chat service, so one small client can talk to several providers. With no key set, the command skips honestly and says so. With a key, the remote model can ask for the write, and the harness still decides whether it runs and still checks the bytes itself.

You will learn how to hide a remote model behind the same one-method contract as a fake one, how a tool request from a real model gets translated into a harness decision, why a missing key should end in a clean, clearly labeled skip instead of a pretend success, and why the fake model stays the backbone of the test suite even after a live one works.

Starting simple: the key, the skip, and the guest

You want hello.txt to hold the two letters ok, and this time a remote chat model is the one that asks for the write. Set an API key, the secret a provider issues so your program can call its application programming interface (API), and npm run live sends the task over the web, writes a text log at transcripts/live-allow.jsonl, and then reads hello.txt itself to check the bytes. Leave the key unset and the same command prints one line, live skipped: OPENAI_API_KEY (or OPENROUTER_API_KEY) not set, and exits 0. The folder is not dressed up as a success. The skip says the key was missing, and it stops there.

The small runtime wrapped around the model is the harness. It owns the yes before a tool runs, the no that means the tool never starts, the text log, and the byte check. Yes before the write is Allow. No, so the write never starts, is Deny. The log is one JavaScript Object Notation object per line, a format people call JSONL. The model is only a guest. That guest can be a script with no network call, or a live client that sends the key as Bearer auth. Bearer means the secret goes in the Authorization header as the word Bearer, then the key. Same task either way. Create hello.txt containing exactly ok.

The call itself is HTTP (Hypertext Transfer Protocol), the request protocol the web already uses.

The code is public:

https://github.com/ashishpatill/harness-from-scratch

Clone it and run npm run live once with no key, so you see the skip. Set a key when you want the web request. Both guests share one method. The harness still owns Allow and the bytes.

One method

Model is a TypeScript interface (TypeScript is JavaScript with type annotations, and an interface is a named promise about which methods an object has) with a single method, decide. Messages and the tool specs go in. A decision comes out. The loop does not look at how decide was written.

export interface Model {
  decide(messages: Message[], tools: ToolSpec[]): Promise<Decision>;
}

FakeModel is the scripted guest. Fixed modes, no network call, the one continuous integration can re-run forever. Continuous integration, usually shortened to CI, is the robot that re-runs the suite. Mode ok proposes write_file for hello.txt with content ok, then stops once a tool observation exists. An observation is the note the tool returns after it runs. Keep FakeModel for the everyday check. The live client is the optional guest on the same interface.

OpenAICompatibleClient is the live guest. It also implements Model. On decide it sends a POST to ${baseUrl}/v1/chat/completions with fetch, the web request function built into Node, sends the Bearer key, maps the first tool_calls entry (the provider's list of tools the model wants to use) into a harness decision, and maps plain text content into stop. POST is the HTTP verb that sends a body. The client waits for the full JSON. Retries and a vendor software development kit (SDK) stay out of this file. The adapter can be a little awkward. The interface stays one method.

The helper clientFromEnv reads the process environment. If neither OPENAI_API_KEY nor OPENROUTER_API_KEY is set, it returns null. That null is what the command turns into the skip line. When only the OpenRouter key is set, the client defaults the base URL to the API origin of OpenRouter, a service that relays requests to many model providers, and picks a default model name for that host. OPENAI_BASE_URL is the origin only, meaning the scheme and host such as https://api.openai.com. The client appends /v1/chat/completions itself. OPENAI_MODEL is optional. You can point the same class at any chat-completions endpoint (a web address that accepts these requests) that speaks tools this way.

What the live command does

The live branch in src/cli.ts calls clientFromEnv. If that returns null, it prints the skip line and exits 0. Otherwise it uses the client as the model, bakes FixedGate (a helper with a pre-set answer) with allow, and sets the transcript to transcripts/live-allow.jsonl. The task string matches the ordinary allow path.

FixedGate is a helper that returns a pre-set allow, deny, or timeout from the moment you create it. Timeout is a third pre-set word so a test can skip the write without waiting on a clock. For this demo the word is allow, so CI never waits on a keyboard. A typed y or n on your laptop is a different command. This one journals the approval the same way, with the answer already chosen.

if (scenario === "live") {
  const client = clientFromEnv();
  if (!client) {
    console.log("live skipped: OPENAI_API_KEY (or OPENROUTER_API_KEY) not set");
    process.exit(0);
  }
  model = client;
  gate = new FixedGate("allow");
}

After allow, the tool registry runs the tool. For this task that is usually write_file. The harness does not trust the model's stop sentence. On stop it reads hello.txt and checks the exact bytes ok. That read is the exact-byte proof. Wrong bytes fail. A missing file fails. The journal records the proof beside stop. The guest changed. The check did not.

If the remote model proposes run_command with an argument list instead of the write, the same Allow check still runs, and the command still starts inside the confined working directory. Only the guest that called decide changed.

npm run live

Run it once with no key. You should see the skip line and exit status 0. A missing key is a clean skip. A made-up file would be a lie, and this command does not tell that lie.

Inside the HTTP guest

Constructor options are the API key, an optional base URL (the default is https://api.openai.com), an optional model name (the default is gpt-4o-mini), and an optional fetchImpl so tests can substitute the network call. Trailing slashes on the base URL are stripped. decide builds a chat-completions body with the tools the harness already registered, sets tool_choice to auto, and posts JSON.

const response = await this.fetchImpl(`${this.baseUrl}/v1/chat/completions`, {
  method: "POST",
  headers: {
    "content-type": "application/json",
    authorization: `Bearer ${this.apiKey}`
  },
  body: JSON.stringify(body)
});

If the HTTP status is not a success, the client throws and includes a short slice of the body. If the provider returns tool_calls, the first call wins for this small agent. The function name write_file needs a string path and string content. The function name run_command needs an argv list of strings (the program name followed by its arguments, each as a separate string) and an optional working directory string. Anything else throws. If there are no tool calls, the trimmed content becomes the stop answer. Empty content becomes the word done.

A little state tracks the pending tool-call id so the next decide can send the assistant tool_calls message plus the tool observation, in the shape this HTTP API expects. That bookkeeping stays inside the guest. The harness loop still speaks only messages and decisions. If a tool observation arrives with no prior tool call, the client throws instead of inventing an id.

When only OPENROUTER_API_KEY is set, it is the same class with a different default origin and a different default model string. You can still override both with OPENAI_BASE_URL and OPENAI_MODEL.

Why the skip stays boring

A fresh clone and CI have to stay green with no secrets in the environment. If live required a key, every new laptop and every pull request runner would fail for the wrong reason. Returning null from clientFromEnv, and exiting 0 from the command, keeps the scripted guest required and the live guest optional.

When a key is set, the live path can fail for ordinary reasons. The network drops. The provider refuses the call. The model proposes a path you did not want. FakeModel stays the backbone of the suite for that reason. Live is the second guest, the one you run when you want the HTTP path. If someone asks whether the live demo passed with no key, the honest answer is that it skipped. Exit 0 means the skip was clean.

Honest limits

The client waits for the full chat-completions JSON. Streaming and retries stay later. So does an official SDK. The path check is a string prefix. An operating-system sandbox stays outside this command. The live command uses FixedGate with allow, rather than a typed y or n. A typed answer is a separate scenario on the scripted guest. A live run can flake whenever a key is present. A green FakeModel suite is the default proof that the harness still works.

Streaming can arrive later behind the same decide method. So can a gate that waits for one typed line, when you want a person to answer a live request. This piece stays on the guest swap, the honest skip, and the same hello.txt check.

What to run

Clone the public repo if you do not have it. You need Node 22 or newer. The script turns on the flag that runs TypeScript without a separate compile step.

git clone https://github.com/ashishpatill/harness-from-scratch
cd harness-from-scratch
npm run live

With no key you should see the skip line and exit 0. With OPENAI_API_KEY or OPENROUTER_API_KEY set, look for transcripts/live-allow.jsonl and for hello.txt reading ok. Open the JSONL. The guest proposed a tool, the journal recorded allow, and the proof says exactBytes true when the run finished cleanly.

With no key, the command exits 0 and does not claim that hello.txt was written. With a key, a clean finish leaves those two letters in the file, records allow in transcripts/live-allow.jsonl, and the proof says the bytes match. The remote model got to ask. The harness still decided whether the write ran, and it still read the file itself.
