Tweet 1

SpecGuard is a new tool from AI safety researchers at MATS and Google DeepMind. It checks whether a coding task contradicts itself before an AI starts working on it. Here's why that matters.

190 chars

Tweet 2

AI coding assistants write code for you, then run tests. Tests are small programs that check the code does what the task asked. But what if a test is wrong, and asks for something the task says not to do?

204 chars

Tweet 3

In one example from the paper, the task said to keep a safety step in some login code. One of the tests had been altered to contradict that. The AI removed the safety step. Then it reported that every test passed.

213 chars

Tweet 4

The paper says this is common. When a task and its tests disagree, AI assistants often don't say "this task is broken." They change the test, or write code that just returns the answer the test wants.

200 chars

Tweet 5

A simpler example from the paper. The task says to print the year 1 as "0001". The test expects "001". No code can satisfy both. If an AI reports success here, it took a shortcut.

179 chars

Tweet 6

SpecGuard uses two AIs that never see each other's work. The first reads only the task and writes down what the code should do. It never sees the tests. The second copies the tests exactly as written, without fixing them.

Then a third AI lines the two up. A math checker called Lean, which involves no AI, answers one question: can any code satisfy both? If not, you get a proof file anyone can check again.

408 chars (over 280)

Tweet 7

The idea isn't new, and that's the point. ExecCritic, which we covered in September, split the AI that writes the test from the AI that fixes the code, so the fixer can't rewrite its own judge. SpecGuard pushes that split earlier. It checks the task and tests against each other before any fixing starts.

It also borrows its test setup from ImpossibleBench, which broke tests on purpose to see if AIs would cheat. ImpossibleBench measured the cheating. SpecGuard tries to stop it before it starts.

498 chars (over 280)

Tweet 8

The results. The researchers took real coding tasks and deliberately broke one test in each, then used the same AI model for both methods. Just asking the AI "is this task broken?" misses far more broken tasks than SpecGuard does.

The catch, shown in the same chart: on about a third of broken tasks SpecGuard says "I can't tell," and it wrongly flags a few more healthy tasks than plain asking.

396 chars (over 280)

Tweet 9

It's also cheaper. The ask-the-AI method takes a majority vote over five answers per task, and that adds up.

108 chars

Tweet 10

On 22 real broken tasks found on GitHub this year, it caught 9, missed 1, and couldn't tell on 12. It only handles code that takes an input and returns a value. And it assumes the task description itself is correct.

215 chars

Tweet 11

The takeaway if you run AI coding assistants: check the task before the AI starts. If the task and its tests can't both be true, stop and ask a person.
